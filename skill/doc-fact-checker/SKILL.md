# Doc Fact Checker — AI 문서 검증·교정

## 왜 이 스킬이 필요한가

AI 초안은 문장이 유창해서 오류가 눈에 잘 띄지 않는다. 실무에서 반복적으로 발견되는 문제는 네 가지다.

1. 그럴듯하지만 근거 없는 수치·통계 (할루시네이션)
2. 존재하지 않거나, 실재하지만 내용이 다른 출처 인용
3. 계산·수식 오류, 단위·표기 불일치
4. 요약과 본문, 표와 서술이 어긋나는 내부 모순

이 스킬은 문서를 **검증 가능한 주장 단위로 분해**한 뒤, 주장 유형별로 가장 확실한 수단(Python 재계산, 실시간 웹 검색, 원문 대조)을 적용하고, **재현 가능한 근거**와 함께 판정과 수정안을 제시한다.

## 검증자 6원칙 — 다른 무엇보다 먼저 지킬 것

틀린 검증 보고서는 원본의 오류보다 더 위험하다. 사용자가 "검증을 통과했다"고 믿게 만들기 때문이다. 검증 과정 자체의 할루시네이션을 막기 위해 아래 원칙을 예외 없이 지킨다.

1. **모든 계산은 Python으로 실행한다.** 합계·비율·성장률·환산 어느 것도 암산하지 않는다. 검산표에는 실행한 계산식을 그대로 기록해 누구든 재현할 수 있게 한다.
2. **'오류 확인' 판정에는 재현 가능한 근거를 반드시 첨부한다.** 재계산 결과, 검색된 출처의 해당 내용, 원문 대조 중 하나 이상. 근거를 붙일 수 없다면 그 판정은 '의심'으로 낮춘다.
3. **검색해서 안 나오면 '오류'가 아니라 '검증 불가'다.** 부재는 증명하기 어렵다. 단, 기관명·연도·수치까지 구체적으로 명시된 인용이 해당 기관의 공식 자료에서 확인되지 않으면 '의심'으로 상향할 수 있다.
4. **기억만으로 '확인됨' 판정을 내리지 않는다.** 시장 규모, 법령 조문, 정책·사업 정보, 인물·직책 같은 외부 사실은 학습 시점 이후 바뀌었거나 애초에 잘못 기억했을 수 있다. 반드시 실시간 검색으로 확인한다. 수학적 사실과 문서 내부 정합성만 도구 실행 결과로 직접 판정한다.
5. **판정문에는 원문을 그대로 인용해 대조한다.** 검증자가 문서를 잘못 읽고 없는 오류를 지어내는 것 역시 할루시네이션이다. 인용 없이 요지만 옮겨 적으면 이 오류를 스스로 발견할 수 없다.
6. **확신도를 구분해 표시한다.** '확인됨'과 '오류'는 근거가 있을 때만 쓴다. 애매하면 '의심' 또는 '검증 불가'로 남긴다. 두 가지로 해석되는 문장은 한 해석을 단정해 오류 판정하지 말고 양쪽을 병기한다.

## 워크플로 — 5단계

### 0단계. 문서 확보와 맥락 파악

- 파일은 `scripts/extract_text.py`로 읽는다. PDF(pdfplumber, 페이지 표식 포함)·DOCX(python-docx, 표 포함)·HWPX(zip+XML, 표 포함)·MD/TXT를 한 개의 마크다운 텍스트로 변환한다.

```bash
python /skills/doc-fact-checker/scripts/extract_text.py <입력파일> --out /tmp/work/document.md
```

  표가 많은 PDF는 텍스트 추출 과정에서 표 구조가 깨질 수 있으니 `pdfplumber`의 `extract_tables()`로 해당 페이지의 표를 다시 뽑아 대조한다. 추출 결과가 비어 있으면(스캔 PDF 등) 검증을 중단하고 '텍스트 추출 실패'를 결과에 기록한다.
- **기준 시점**을 파악한다. 문서가 언제 기준으로 작성됐는지에 따라 "낡은 데이터"와 "틀린 데이터"가 갈린다. 이 구분을 놓치면 멀쩡한 문서를 오류투성이로 판정하게 된다.
- **내부 사실의 검증 한계를 사용자에게 명시한다.** 회사 내부 계약 조건, 미공개 매출, 조직 내부 결정 사항은 웹으로 검증할 수 없다. 근거 자료(계약서, 내부 데이터)를 요청하고, 받지 못한 항목은 '검증 불가(내부 자료 필요)'로 분류해 사용자 확인 목록에 올린다.
- 검증 범위: 기본은 문서 전체다. 사용자가 특정 영역(예: "숫자만 봐줘")을 지정하면 그에 맞추되, 스캔 중 다른 영역에서 치명적 오류를 발견하면 범위 밖이라도 별도로 알린다.

### 1단계. 주장 인벤토리 — 검증하기 전에 전부 추출

먼저 문서 전체를 읽으며 **검증하지 말고 추출만** 한다. 읽으면서 바로 검증하면 앞부분에서 형성된 인상이 뒷부분 판단을 오염시키고(확증편향), 검증에 몰입하느라 주장을 빠뜨린다. 추출과 검증의 분리가 이 스킬의 정확도를 만드는 핵심 장치다.

각 주장에 유형 태그를 붙인다.

| 태그 | 대상 | 검증 수단 |
|---|---|---|
| [계산] | 합계, 비율, 성장률, 단가×수량, 단위 환산 | Python 재계산 |
| [정합] | 요약↔본문, 표↔서술, 시계열 연속성, 용어 일관성 | 문서 내 대조 + Python |
| [사실] | 시장 규모, 통계, 사건, 인물·직책, 제품·기술 정보 | 웹 검색 |
| [출처] | 보고서·기사·논문 인용, URL | web_fetch로 원문 대조 |
| [법령] | 법령명, 조문 번호, 조문 내용, 시행 여부 | 국가법령정보센터 기준 검색 |
| [의견] | 예측, 전략 제언, 가치 판단 | 참/거짓 판정 대상 아님. 단, 근거 제시 여부는 점검 |

숫자는 `scripts/korean_number_parser.py`를 실행해 전수 목록을 확보한다. 눈으로 훑으면 반드시 빠뜨린다.

```bash
python /skills/doc-fact-checker/scripts/korean_number_parser.py /tmp/work/document.md --json > /tmp/work/numbers.json
python /skills/doc-fact-checker/scripts/korean_number_parser.py /tmp/work/document.md
```

파서 출력 하단의 '동일 값 다중 표기' 목록은 2a단계 내부 정합성 검증의 출발점이 된다.

동시에 `references/hallucination-patterns.md`의 위험 신호와 대조해 의심 항목을 미리 표시해 둔다. 위험 신호가 있다고 오류인 것은 아니지만, 검증 우선순위를 정하는 근거가 된다.

### 2단계. 계층별 검증 — 안에서 밖으로

내부 검증(정합·계산)을 먼저, 외부 검증(사실·출처·법령)을 나중에 한다. 내부 검증은 도구 실행만으로 확정적 결론이 나오고 비용이 낮다. 내부에서 이미 무너진 수치는 외부 검증에 시간을 쓸 필요가 없어진다.

**2a. 내부 정합성** — 같은 값이 문서 안에서 일치하는가. 표의 행 합계와 총계, 요약의 수치와 본문의 수치, 연도별 시계열의 연속성, 같은 대상을 가리키는 용어의 통일. 파서 출력의 동일 값 그룹을 대조 자료로 쓴다.

**2b. 계산 재현** — 문서의 모든 수식을 Python으로 다시 세운다. 수식이 명시되지 않은 결과값은 역산으로 의도된 계산을 추정해 검증하되, 추정했다는 사실을 검산표에 명시한다. 도메인별로 자주 틀리는 지점은 `references/domain-checklists.md`의 해당 항목을 참조한다.

**2c. 외부 사실** — 웹 검색으로 확인한다. 출처 우선순위: 정부·공공기관·공식 통계 원자료 → 해당 기업·기관의 공식 발표 → 주요 언론 → 기타. 치명적 판정(결론을 바꾸는 오류)은 서로 독립된 출처 2개 이상으로 교차 확인한다. 검색 결과의 기준 연도가 문서의 기준 시점과 맞는지도 반드시 함께 본다.

**2d. 출처·인용** — 인용된 출처가 (1) 실재하는가, (2) 실제로 그 내용을 말하는가를 나눠서 본다. URL은 web_fetch로 직접 열어 확인하고, 보고서·기사는 검색해 원문의 해당 대목과 문서의 인용을 대조한다. 가장 위험한 유형은 "실재하는 출처 + 다른 내용"이다 — 그럴듯해서 아무도 의심하지 않는다.

**2e. 법령·규정** — 법령명, 조문 번호, 조문 내용, 현행 여부를 국가법령정보센터(law.go.kr) 기준으로 확인한다. `law_search`·`law_article` 도구가 제공되면 그것을 우선 쓴다: `law_search(법령명)`으로 법령ID를 얻고 `law_article(법령ID, 조 번호)`로 현행 조문 원문과 시행일자를 받아 문서의 인용과 대조한다. `exists=false`는 "해당 조가 현행 법령에 없음"의 확정 근거이므로 ❌ 오류 판정이 가능하다. 도구가 없으면 web_search/web_fetch로 law.go.kr을 확인한다. 법령 인용은 AI 할루시네이션 최다 발생 영역이다. 실재하는 법의 존재하지 않는 조문, 폐지·개정 전 조문의 인용, 법률·시행령·시행규칙의 혼동(세 가지는 별개 법령이다)을 중점적으로 본다.

### 3단계. 판정과 심각도

판정은 4단계로 나눈다.

| 판정 | 기준 |
|---|---|
| ❌ 오류 확인 | 재현 가능한 근거로 틀렸음이 확인됨 |
| ⚠️ 의심 | 오류 정황이 있으나 확정 근거가 부족함 |
| ❓ 검증 불가 | 검증 수단이 없음 (내부 자료 필요, 출처 미상 등) |
| ✅ 확인됨 | 재계산 또는 신뢰할 수 있는 출처로 일치가 확인됨 |

심각도는 3단계로 나눈다.

| 심각도 | 기준 | 예 |
|---|---|---|
| 🔴 치명 | 문서의 결론·의사결정을 바꿈 | 핵심 수치 오류, 존재하지 않는 법적 근거, 조작된 핵심 통계 |
| 🟠 중대 | 사실과 다르지만 결론은 유지됨 | 보조 통계 오류, 부정확한 인용, 계산 착오 |
| 🟡 경미 | 신뢰도에 흠집을 냄 | 반올림 불일치, 단위 표기 혼용, 오탈자 |

### 4단계. 보고서 작성과 교정본

`references/report-template.md` 양식으로 검증 보고서를 작성한다. 발견 항목이 많으면(대략 15건 이상) 파일로 저장해 전달하고, 적으면 대화로 바로 보고한다.

사용자가 원하면 교정본을 만든다. 원문의 형식과 문체를 유지하고, 수정한 부분은 알아볼 수 있게 표시한다(변경 목록 병기 또는 수정 표시). 교정은 오류 제거이지 내용 보강이 아니다 — 검증되지 않은 내용을 교정 과정에서 새로 추가하지 않는다.

## 자주 빠지는 함정

- **%와 %p 혼동**: "점유율이 10%에서 15%로 5% 증가"는 틀렸다. 5%p 증가이고, 상대 증가율은 50%다.
- **CAGR와 단순평균 혼동**: 3년간 100→160은 연평균 20%가 아니라 (160/100)^(1/3)−1 ≈ 17.0%다.
- **단위 혼용**: 억/만/천, 원/달러가 한 표 안에 섞이면 합계가 반드시 의심 대상이다.
- **반올림 누적**: 행별 반올림 값의 합이 총계와 1~2 어긋나는 것은 오류가 아닐 수 있다. 원자료 정밀도를 확인하고 경미로 분류한다.
- **시점 차이를 오류로 오판**: 문서 작성 시점 기준으로는 맞았던 수치일 수 있다. "틀림"이 아니라 "업데이트 권장"으로 구분한다.
- **모호한 원문의 단정 해석**: 두 가지로 읽히는 문장은 한 해석만 골라 오류 판정하지 않는다. 양쪽 해석을 제시하고 명확한 서술로 고치기를 권한다.
- **검증자의 과잉 확신**: "이 정도는 안다"는 느낌이 들수록 검색한다. 익숙한 주제일수록 낡은 기억으로 판정할 위험이 크다.

## 산출물

1. **검증 보고서** (기본): 종합 신뢰도 등급, 오류 목록(심각도순, 근거·수정안 포함), 검산표, 사용자 확인 필요 목록. `references/report-template.md` 양식의 마크다운으로 `report.md`에 저장한다.
2. **구조화 결과** (앱 연동용, 기본): 보고서와 같은 내용을 `references/result-schema.md`의 JSON 스키마로 `result.json`에 저장한다. 보고서와 JSON의 판정·건수는 반드시 일치해야 한다.
3. **교정본** (요청 시): 수정 표시가 된 원문 형식 유지본 `corrected.md`
4. **검증 로그** (요청 시): 실행한 계산식, 검색어, 참조 출처의 전체 기록 `log.md`

## 실행 환경 — API 컨테이너에서 돌아갈 때

이 스킬이 Claude API의 코드 실행 컨테이너에서 실행되는 경우 다음을 지킨다.

- 스킬 파일은 `/skills/doc-fact-checker/` 아래에 있다. 스크립트·참고 파일은 이 절대경로로 부른다.
- 검증 대상 파일은 요청에 첨부된 컨테이너 업로드 파일이다. 작업은 `/tmp/work/` 아래에서 한다.
- 컨테이너는 인터넷이 막혀 있다. Python `requests`·`urllib`로 외부에 접근하지 말고, 외부 사실·출처 확인은 반드시 `web_search`·`web_fetch` 도구로 한다. 계산·정합성·파일 처리만 Python으로 한다.
- 추가 패키지 설치는 불가하다. 사전 설치된 pdfplumber, pypdf, python-docx, pandas, numpy만 쓴다.
- 최종 산출물은 마지막 bash 명령에서 `$OUTPUT_DIR`로 복사하고 `ls "$OUTPUT_DIR"`로 확인한다. 예: `cp /tmp/work/result.json /tmp/work/report.md "$OUTPUT_DIR/" && ls "$OUTPUT_DIR"`. `$OUTPUT_DIR` 밖에 둔 파일은 호출자에게 전달되지 않는다.
- 마지막 텍스트 응답에는 `result.json`의 내용을 `<result_json>` 태그 안에 그대로 한 번 더 넣는다. 파일 전달이 실패해도 결과를 복구할 수 있게 하기 위한 안전장치다.
