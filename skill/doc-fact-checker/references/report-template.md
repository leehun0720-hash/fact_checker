# 검증 보고서 표준 양식

아래 구조를 따른다. 항목이 적으면(대략 5건 미만) 대화에서 간략 형식으로 보고해도 되지만, 판정·근거·수정안 3요소는 생략하지 않는다.

## 신뢰도 등급 기준

| 등급 | 기준 | 의미 |
|---|---|---|
| A | 치명·중대 0건, 경미 소수 | 그대로 사용 가능 |
| B | 치명 0건, 중대 1~2건 | 지적 항목 수정 후 사용 가능 |
| C | 치명 1건 이상 또는 중대 3건 이상 | 주요 수정 후 재검토 필요 |
| D | 핵심 논거가 검증 실패 | 전면 재작성 권고 |

검증 불가 항목이 핵심 주장의 30%를 넘으면 등급과 별도로 **[근거 보강 필요]** 플래그를 붙인다. 등급이 좋아도 검증하지 못한 문서는 신뢰할 수 있는 문서가 아니다.

---

## 양식

```markdown
# 문서 검증 보고서

| 항목 | 내용 |
|---|---|
| 검증 대상 | (문서명, 버전, 분량) |
| 검증 일자 | YYYY-MM-DD |
| 문서 기준 시점 | (문서가 작성된 기준 시점) |
| 검증 범위 | 전체 / 특정 섹션 |
| 사용 수단 | Python 재계산 n건, 웹 검색 n회, 원문 대조 n건 |

## 1. 종합 판정

**신뢰도 등급: B — 부분 수정 후 사용 가능**

(2~3문장 요약: 무엇이 문제이고 무엇이 건전한지)

| 판정 | 건수 |
|---|---|
| ❌ 오류 확인 | n |
| ⚠️ 의심 | n |
| ❓ 검증 불가 | n |
| ✅ 확인됨 | n |

## 2. 오류 목록 (심각도순)

### 🔴 치명-1. 표 합계 오류
- **위치**: 4쪽 '예산 계획' 표
- **원문**: "합계 2.7억원"
- **판정**: ❌ 오류 확인
- **근거**: 항목 재계산 1.2 + 0.8 + 0.5 = 2.5억원 (Python 실행 결과)
- **수정안**: "합계 2.5억원" — 또는 항목 누락 여부를 확인해 항목 추가

### 🟠 중대-1. …
(같은 구조 반복)

## 3. 의심 및 검증 불가 항목

| # | 위치 | 원문 | 분류 | 사유 | 권장 조치 |
|---|---|---|---|---|---|
| 1 | 2쪽 | "중소기업의 73.4%가…" | ⚠️ 의심 | 출처 기관 공식 자료에서 해당 조사 미확인 | 원출처 확보 또는 삭제 |
| 2 | 5쪽 | "당사 기존 계약 단가 500만원" | ❓ 검증 불가 | 내부 자료 필요 | 계약서 대조 (사용자 확인) |

## 4. 수치 검산표

| 위치 | 문서 값 | 재계산 값 | 일치 | 계산식 |
|---|---|---|---|---|
| 4쪽 표 | 2.7억 | 2.5억 | ❌ | 1.2e8 + 0.8e8 + 0.5e8 |
| 5쪽 | 5,000만 | 5,000만 | ✅ | 5_000_000 × 10 |

(역산으로 추정한 계산식에는 "추정" 표기)

## 5. 확인된 핵심 주장

(검증을 통과한 핵심 주장을 근거 출처와 함께 2~5개. "확인됨"에도 근거를 남겨야 보고서 자체가 검증 가능해진다)

## 6. 권장 조치

1. (우선순위 1 — 치명 오류 수정)
2. (우선순위 2 — 의심 항목의 원출처 확보)
3. (우선순위 3 — 사용자 확인 필요 항목 목록 전달)
```

## 작성 시 유의

- 원문 인용은 그대로 옮긴다. 요약해 옮기면 검증자의 오독을 발견할 수 없다.
- 근거 없는 판정 문장을 쓰지 않는다. 근거를 못 쓰겠으면 판정을 '의심'으로 낮춘다.
- 수정안은 실행 가능해야 한다. "확인 필요"로 끝내지 말고, 무엇을 어디서 확인할지까지 쓴다.
- 잘한 부분(확인된 항목)도 기록한다. 오류만 나열된 보고서는 문서 전체가 부실하다는 착시를 만든다.
